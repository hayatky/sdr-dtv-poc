# WebUIの構成と状態管理

利用者向けの画面と操作は[操作ガイド](webui-guide.md)、APIの入出力は[API仕様](api.md)を参照してください。
本書は、WebUIを変更する際に維持する処理・表示・終了動作をまとめています。

## 構成

Vue 3とhls.jsの固定したバージョンを同梱し、FastAPIからUI・API・HLSを同一オリジンで配信します。
Node.js/npm、フロントのビルド、実行時CDNは不要です。Vue Routerは使わず、
「接続・スキャン」「視聴」「録画」の三つのタブをURLのハッシュで選びます。

| ファイル（`src/sdr_dtv_poc/static/`） | 役割 |
|---|---|
| `index.html` | 外部CSS・JavaScriptを読み込むページの骨組み |
| `style.css` | 色・文字・余白、画面幅に応じた配置、ダークモード |
| `app.js` | 画面の描画、タブ、状態管理、ポーリング、開始・停止操作 |
| `api.js` | HTTP通信、CSRF、APIの応答から画面表示用の値への変換 |
| `player.js` | 標準HLS/hls.jsの接続、再生状態と失敗の通知、終了時の解放 |
| `mock.js` | `?mode=mock`で明示的に選ぶ表示確認用の模擬データ |

通常の画面は実APIを使います。合成TSもAPIで処理し、映像・音声を再生・録画します。
`?mode=mock`は画面表示の確認用で、受信・録画APIやA/V再生を実行しません。
HTTP通信に失敗しても模擬データへ自動的に切り替えません。

## APIとの接点

一覧APIからsessions/scans/recordingsの状態を取得します。`GET /api/status`はありません。
`api.js`の`status()`はこれらをまとめる画面側の関数です。
局の選択には保存済みServiceの`id`を`service_key`として渡します。
放送側の整数`service_id`とは区別します。選局は600秒・HLS有効を指定します。

画面の残り時間は`deadline_at`と端末の時計から計算する推定で、受信や録画の停止制御には使いません。
録画開始の可否と300秒期限はサーバーが判断します。全体の復元状態や正確な空き容量を
一覧だけで正常と断定せず、診断とAPIの`restore_unverified`、`storage_full`等を表示します。
表示用の段階・残り時間を、APIが返す追加フィールドとして扱わないでください。

変更操作にはOriginとCSRFトークンを付けます。403ではbootstrapと現在の状態を取り直し、
拒否された変更要求を自動的には再実行しません。開始要求の結果が不明なときは同じ`request_id`を保持し、
一覧で受理済みかを照合します。照合できた場合は保留を解消し、明示的な再送には同じIDを使います。

## 状態の更新と終了処理

- 再読込み、通信復帰、別タブ、`pageshow`では現在の状態を取得し、受信・スキャン・録画を自動開始しません。
- 読取りのポーリングは一つだけです。`pagehide`後に、古い要求の終了処理から再開しません。
- 選局時はバックエンドが旧sessionの停止・回収を待ちます。画面は切替時に旧映像を解放します。
- 操作の世代と対象IDを照合し、古いHTTP応答・HLSイベント・`play()`のPromiseを別の再生へ適用しません。
- タブ変更・受信停止・再生対象変更・`pagehide`では、不要になったプレイヤー、イベント、取得、タイマーを終了します。
  同じ対象の状態更新ではvideo要素を作り直しません。
- 通信やページの復帰時は、選択中の録画Playbackの状態も取得してから接続します。
- ブラウザーを閉じてもサーバーは有限期限まで処理を続けます。即時停止は明示した停止操作で行います。

## プレイヤー・録画

対応を申告するブラウザーでは標準HLSを使い、それ以外は同梱hls.jsを使います。
標準HLSが実際には非対応エラーを返した場合に限り、一度hls.jsへ切り替えます。
自動再生拒否では手動の再生ボタンへ案内し、音声を自動的に無効にしません。

録画中は選局・スキャン・二重録画を禁止し、APIの409も案内します。
録画だけの手動停止は正常終了で、受信を先に止める場合は途中終了になることを確認画面に示します。
`failed`や`partial`の録画を完了と表示しません。
再生・ダウンロードでは`completed`、`partial=false`、`file_available`、`download_url`を確認します。
APIが返した登録済みURLを使い、任意のパスやURLを入力させません。

録画再生はCSRF付きPOSTで明示的に開始します。以後はPlaybackの状態とURLを取得し、
再生変換やブラウザーの失敗を、元の録画の状態と区別します。失敗ジョブへPOSTを繰り返しません。
録画削除は利用者へ確認し、録画中・再生処理中の拒否と、キャンセル・失敗を表示します。
保存・削除・復旧の詳細は[API仕様](api.md)と[復旧手順](recovery.md)を参照してください。

## 表示の規則

- 実機ライブ・保存TS・合成TSを区別します。模擬画面の表示確認も、合成TSの再生と混同しません。
- 局名・リモコン番号・物理チャンネルを表示し、未取得の名前は推測で補いません。
  `service_id`等は「技術的な値を表示」の詳細欄へ置きます。
- 保存された局は前回のスキャン結果です。「受信中」は現在動いている受信の局にだけ付けます。
- 信号検出、TMCC、番組情報と、実際のA/V再生成功を区別します。
  映像下の段階表示で、受信・番組データ・CAS・変換・ブラウザーのどこで止まったかを案内します。
- 日時は端末のタイムゾーン、残り時間は分・秒で表示します。
- 局名などの文字列をHTMLとして解釈せず、Vueの文字列として描画します。
- 通信断では最後に取得した状態と現在の成功を区別し、必要な操作を文で示します。

## 配色・画面幅・アクセシビリティ

色と余白は`style.css`の`:root`で管理します。正常・注意・失敗などの状態は、色だけでなく記号と文字を併記します。
OS標準フォントを使用し、フォントの実体は同梱しません。ダークモードは`prefers-color-scheme`、
動きを減らす設定は`prefers-reduced-motion`に従います。

タブは左右矢印・Home・Endで移動でき、選択中だけがTabキーの移動先になります。
「本文へ移動」のリンクとフォーカス表示を備え、タブ移動や再生欄を閉じる操作ではフォーカスを戻します。
入力部品にはラベルを付けます。状態の変化は`aria-live`で通知し、毎秒の残り時間は読み上げ対象にしません。

画面幅が900px未満では視聴画面を一列に、700px以下では局の表をカードにし、420px以下ではタブを詰めます。
操作対象の高さは44px以上を基本とします。配色・余白の具体値はCSSを参照してください。

## 検証

API通信・プレイヤー・ページの終了処理は`tests/webui-lifecycle.js`、実画面の操作は
`scripts/smoke-webui.py`で確認します。実行方法と環境の準備は[開発手順](development.md)に記載しています。
標準HLSを模擬した試験をSafariの実行結果とは扱いません。
機械的なA/Vの確認、人による視聴、実機での受信は[検証結果](validation.md)で区別しています。
