## この資料と画面の位置づけ

- `?mode=mock`の画面は**表示確認用のデモ**です。局・映像・録画はすべて架空の模擬データで、
  画面の操作から受信・スキャン・録画のAPIを呼びません。サーバーから取得するのは
  HTML・CSS・JavaScriptのファイルだけです。
- 動画の領域には自作のテストパターンを「合成表示」と明記して表示します。
  映像・音声を再生した、または再生を確認したとは表示しません。
- 実APIとHLSへの接続、受信中の映像・音声、実機での録画は#29以降で確認します。
  この画面で確認できたことを、実機での受信や再生の成功とは扱いません。

## 起動と確認の方法

アプリの起動はREADMEと同じです。UIの確認だけなら合成TSの生成は不要です。

```sh
uv sync --locked
uv run --locked uvicorn sdr_dtv_poc.app:create_app --factory \
  --host 127.0.0.1 --port 8000 --workers 1 --no-proxy-headers --no-access-log \
  --timeout-graceful-shutdown 10
# 模擬画面だけの確認は http://localhost:8000/?mode=mock を開く
```

画面上部の「デモの状態を切り替える」で、再現する状態と模擬の時間の速さを選べます。
URLでも指定できます。例: `http://localhost:8000/?mode=mock&demo=recording_partial&speed=10#watch`。
`demo`はシナリオ名、`speed`は`1`・`10`・`30`、`#scan`・`#watch`・`#recordings`はタブです。
模擬データはページ内だけに保持し、再読込すると最初の状態に戻ります。

| シナリオ名 | 再現する状態 |
|---|---|
| `normal` | 保存された局と録画がある通常の状態（既定） |
| `first_run` | 初回。保存された局と録画がない |
| `scan_none` | スキャンで局が見つからない |
| `scan_fail` | スキャンが途中で失敗する |
| `restore_unknown` | 受信機の設定を元に戻せたか未確認で、開始が止められている |
| `storage_low` | 保存先の空き容量が足りない |
| `offline` | サーバーと通信できない |
| `cas_fail` | カードによる復号に失敗する |
| `transcode_fail` | 映像の変換（HLS）に失敗する |
| `player_fail` | ブラウザーで再生できない |
| `short_session` | 最初の受信の残り時間が少なく、5分の録画を開始できない |
| `recording_partial` | 録画が空き容量の不足で途中終了する |

## 画面構成

一つのページに、常に表示する共通部分と三つのタブを置きます。
Vue Routerは使わず、選択中のタブだけをURLのハッシュ（`#scan`等）へ記録します。

```text
┌───────────────────────────────────────────────────────────┐
│ SDR地上波テレビ [デモ表示]          現在の状態: ● 録画中 架空… 残り 3:12 │ ← 画面上部に固定
│ [接続・スキャン] [視聴 ●] [録画]                                    │
├───────────────────────────────────────────────────────────┤
│ ◆ 表示確認用のデモです（紫の破線）  ▸デモの状態を切り替える           │ ← 常に表示
│ （通信断・復元未確認・容量不足の案内。該当するときだけ）               │
│ タブの内容                                                         │
└───────────────────────────────────────────────────────────┘
```

- ヘッダーの「現在の状態」は、どのタブにいても受信・録画・スキャンの状況が分かるように
  一行で示します。録画中は視聴タブに●、スキャン中は接続・スキャンタブに…を付けます。
- デモの案内は紫の破線の枠と「デモ表示」の札で統一し、ヘッダーの札は常に見えます。

### 1. 接続・スキャン

1. **接続を確認する**: 入力元（実機ライブ・保存TS・模擬入力）を選んで確認します。
   保存先の空き容量、合成テスト信号のファイル（模擬入力のときだけ）、映像の変換、受信ボード、
   受信処理のプログラム、B-CASカード、カードを使う復号ツールを一行ずつ表示します。
   確認では受信を開始しないことを画面に書きます。未確認・失敗の項目には次に行う操作を添えます。
2. **局を探す（スキャン）**: 範囲は「UHFの全範囲（13〜52ch）」「低い側」「高い側」
   「範囲を指定する」から選びます。特定の地域の局配置を前提にしたプリセットは置きません。
   スキャン中は進捗バー、調べているチャンネル、見つかった局の数、中止ボタンを表示します。
3. **保存された局**: 過去のスキャン結果を、リモコン番号・局名・物理チャンネル・
   確認できた段階・「視聴する」ボタンの表で表示します。狭い画面では一局ずつのカードにします。
   service IDは「技術的な値を表示」の中に置きます。

### 2. 視聴

```text
広い画面（900px以上）                      狭い画面
┌──────────────────────┬──────────┐      局が未選択のとき: 局の一覧 → 映像 → 録画
│ 局名 [入力元]           │ 局を選ぶ  │      選局後:          映像 → 録画 → 局の一覧
│ ┌──────────────────┐ │ 実機…     │
│ │ 映像（合成表示）     │ │ 保存TS    │
│ └──────────────────┘ │ 合成…     │
│ 受信→番組データ→復号→変換→表示 │          │
│ 受信の残り時間 [受信を停止する] │          │
├──────────────────────┤          │
│ 録画 ● 0:42 / 5:00 残り 4:18   │          │
│ [録画を停止する]               │          │
└──────────────────────┴──────────┘
```

- 局の一覧は入力元ごとに「実機で受信する局（前回のスキャン結果）」「保存したTSファイル」
  「合成テスト信号」に分けます。受信中の局だけに「▶ 受信中」を付けます。
- 映像の下に、受信から表示までの五つの段階（電波の受信、番組データ、カードによる復号、
  映像の変換、ブラウザーでの表示）を並べ、どこで止まったかを分けて示します。
- 受信は最大10分で自動的に停止することと、その残り時間を表示します。

### 3. 録画

- 一覧の各行に、録画時の局名、開始日時、長さ、ファイルサイズ、入力元、状態
  （完了・途中で終了・中断（途中まで）・録画中）と終了理由を表示します。
- 「再生する」は合成表示の再生欄を一覧の上に開きます。「TSファイルをダウンロード」は、
  デモではダウンロードしないことを案内するだけです。途中で終了した録画では両方を無効にし、
  理由を書きます（後述の「PR #32時点の仕様と、当時#29へ残した接続作業」を参照）。

### 現在の画面と操作

実際のAPIに接続した画面は、[画面付きの操作ガイド](webui-guide.md)を参照してください。
ダークモードで、合成データのスキャン・視聴・録画再生を紹介しています。
この設計記録の模擬デモに関する説明と、現在のAPIに接続した動作は区別してください。

## 操作フロー

### 初回から録画の再生まで

```text
接続を確認する → 局を探す（範囲を選んで開始）→ 保存された局で「視聴する」
  → 視聴タブ: 選局中 → 映像を準備中 → 再生を準備中 → 表示中
  → 録画を開始する → 録画中（残り時間）→ 手動停止 または 5分で自動停止
  → 録画タブで確認 → 再生する／TSファイルをダウンロード → 受信を停止する
```

### 局の切り替え

1. 別の局を選ぶと、すぐに映像の領域と受信の段階表示を消し、見出しを新しい局名にします。
2. 前の受信の停止を要求し、停止が終わるまで「前の受信を停止しています…」と表示します。
3. 停止を確認してから、新しい局の受信を開始します。
4. 前の受信の局名・状態・技術的な値は、切り替え中に表示しません。
   遅れて届いた前の受信の応答はIDを照合して捨てます。

停止の確認は最大15秒待ちます。終わらない場合は「前の受信を停止できませんでした」と表示し、
自動では再試行しません。

### 録画中に禁止する操作

録画中は次の操作のボタンを無効にし、理由と次に行う操作を近くに書きます。
画面で止めるだけでなく、APIでも拒否する必要があります（模擬データでも拒否します）。

| 操作 | 画面の表示 |
|---|---|
| 別の局を選ぶ | 録画中は局を切り替えられません。先に録画を停止してください。 |
| スキャン | 録画中はスキャンできません。先に視聴タブで録画を停止してください。（視聴タブへ移動するボタン） |
| 二つ目の録画 | 録画開始ボタンを表示せず、録画中の表示と停止ボタンだけを置く |
| 受信を停止する | 「録画中です。受信を停止すると録画も停止します。」と確認する。Escキーで取り消す |

視聴中のスキャンは「先に受信を停止してください」と案内し、その場に「受信を停止する」ボタンを置きます。
スキャン中の選局は「スキャンが終わるのを待つか、中止してください」と案内します。

### 再読込・別のタブ

画面を開いたときと定期的な更新で、動作中の受信・スキャン・録画のIDを取得し、
そのIDの状態を表示するだけにします。再読込や別のタブを開いたことで新しい受信を開始しません。
模擬データはページごとに独立しているため、この動作はデモでは再現できません。#29で確認します。

## 主要な状態と表示

「次の操作」は画面に書く内容の要約です。判定に使う項目のうち「（仮）」はAPIに未定義です。

| 状態 | 表示 | 次の操作 | 判定に使う項目 |
|---|---|---|---|
| 読み込み中 | ヘッダーに「読み込んでいます…」 | 待つ | 初回の応答前 |
| サーバーと通信できない | 赤い案内。最後に通信できた時刻。録画はサーバー側の期限で止まること | 自動再接続（5秒ごと）、「今すぐ再接続する」 | 通信の失敗 |
| 受信機の設定を戻せたか未確認 | 赤い案内。開始系のボタンを無効化 | 受信機の状態を確認し、復旧の記録を残す | `restore`（仮: 全体の状態として取得） |
| 保存先の空き容量が足りない | 黄色の案内。選局・録画・スキャンを無効化 | 空き容量を増やして接続を確認し直す | 診断の`storage`、`storage_full` |
| 接続を確認中 | ボタンが「確認しています…」 | 待つ | 診断APIの応答待ち |
| 確認結果 | 項目ごとに「使用できます」「見つかりません」「問題があります」「未確認」「この入力では不要」 | 未確認・失敗の項目の案内に従う | 診断の`checks` |
| 局が保存されていない（初回） | 空の状態の説明 | スキャンを開始する | 局一覧が空 |
| スキャン中 | 進捗バー、調べているch、見つかった局の数 | 待つ、または中止する | scanの`state`等（仮） |
| スキャン完了 | 緑の案内「N局を保存しました」 | 視聴タブで局を選ぶ | `end_reason=eof`かつ保存済み（仮） |
| スキャン中止 | 「以前の一覧はそのまま残しています」 | 必要なら再スキャン | `end_reason=requested` |
| 局が見つからない | 黄色の案内。以前の一覧を残す | 接続と範囲を確認して再スキャン | 見つかった局が0 |
| スキャン失敗・時間切れ・中断 | 理由と、以前の一覧を残したこと | 接続を確認、範囲を狭めて再スキャン | `state=failed/interrupted`、`end_reason=deadline` |
| 選局中 | 「前の受信を停止しています…」「受信を開始しています…」 | 待つ | 画面側の操作状態、sessionの`starting` |
| 映像を準備中 | 「映像を準備しています…」 | 待つ | 変換の状態（仮: `health.hls`） |
| 再生を準備中 | 「再生を準備しています…」 | 待つ | プレイヤーの状態（#29） |
| 合成表示中 | テストパターンと「合成表示／映像・音声は再生していません」 | 録画を開始できる | 同上 |
| カードによる復号に失敗 | 段階表示の「カードによる復号：失敗」と赤い案内 | カードを確認し、受信を停止して選局し直す | `health.cas`（仮） |
| 映像の変換に失敗 | 段階表示の「映像の変換：失敗」と赤い案内 | 受信を停止して選局し直す | `health.hls`（仮） |
| ブラウザーで再生できない | 段階表示の「ブラウザーでの表示：失敗」 | 「再生をやり直す」、別のブラウザー | プレイヤーのエラー（#29） |
| 受信を停止中・停止 | 「受信を停止しています…」、停止理由 | もう一度局を選ぶ | sessionの`stopping`、`end_reason` |
| 受信が途中で終了 | 黄色の案内と理由 | もう一度局を選ぶ | `partial`、`state=failed` |
| 録画中 | 赤い枠、●録画中、経過/5:00、残り、進捗バー | 録画を停止する | recordingの`state`（仮） |
| 録画完了 | 緑の案内「録画を保存しました（5:00）」 | 録画タブで確認する | `end_reason=deadline/requested` |
| 録画が途中で終了 | 黄色の案内と理由 | 録画タブで確認する | `partial`、`end_reason` |
| 録画の残り受信時間が不足 | 録画開始ボタンを無効にし、受信の残り時間を示す | 受信を停止して選局し直す | sessionの残り時間が305秒未満 |

## 表記の規則

- **入力元**は三種類を常に区別し、色だけでなく記号と枠線でも見分けられるようにします。
  「● 実機ライブ」（実線）、「■ 保存TS」（二重線）、「◆ 模擬入力」（破線）。
  局名の横、局の一覧、録画の一覧、ヘッダーに表示します。
- **物理チャンネル・リモコン番号・service ID**: 通常の画面ではリモコン番号・局名・物理チャンネルを
  表示し、service IDは「技術的な値を表示」に置きます。リモコン番号が取れない局は「番号なし」、
  局名が取れない局は「局名未取得」と斜体で表示し、推測した名前で埋めません。
- **過去の検出と現在の受信**: 保存された局には「前回の検出：日時（スキャン結果。現在の受信状態では
  ありません）」と書きます。「受信中」は現在動いている受信の局にだけ付けます。
  確認できた段階は「信号のみ検出」「受信情報（TMCC）まで確認」「番組情報まで確認」と分けます。
- **時刻と時間**: 日時は端末のタイムゾーンで`YYYY/MM/DD HH:mm`、残り時間は`分:秒`です。
  読み上げ用の値は「4分12秒」の形にします。
- **専門的な値**（state、end_reason、ID、service ID、データ量等）は各欄の
  「技術的な値を表示」（開閉できる詳細欄）に置き、通常の文にAPI名を出しません。
- **局名などサーバーから受け取る文字列**は、すべてVueの文字列の子要素として描画します。
  `v-html`・`innerHTML`は使いません。模擬データには`<b>…</b> & "…"`を含む架空の局名を入れ、
  そのまま文字として表示されることを確認しています。

## デザインの規則

色・文字・余白は`style.css`の`:root`にまとめ、部品はこの規則だけで組み立てます。

| 用途 | ライト | ダーク | 使う場所 |
|---|---|---|---|
| 本文 / 背景 | `#1b1f24` / `#f5f6f8` | `#e9ebef` / `#121418` | 全体 |
| 補足の文字 | `#4f5764` | `#aab1bc` | 説明、時刻、詳細欄 |
| 操作（主） | `#1b5bc7` | `#8ab0ff` | 主ボタン、選択中のタブ、選択中の局 |
| 正常 | `#16703a` / `#e4f3e9` | `#74d39c` / `#16301f` | 使用できます、完了、受信中 |
| 注意 | `#8a5300` / `#fdf1d8` | `#f2c35e` / `#362a10` | 未確認、途中で終了、開始できない理由 |
| 失敗 | `#b3261e` / `#fce8e6` | `#ff9a8f` / `#3b1a17` | 失敗、通信断、復元未確認、停止ボタン |
| 情報 | `#1b5bc7` / `#e5edfb` | `#8ab0ff` / `#1f2c47` | 選局中、スキャン中、合成表示 |
| デモ | `#5f3596` / `#f2ebfb` | `#cfb0f7` / `#2a2040` | デモの案内、模擬入力、合成表示の注記 |
| 録画 | `#c4122f` | `#ff7088` | 録画中、録画ボタン |

- 文字と背景の組み合わせのコントラスト比を計算し、すべて4.5:1以上であることを確認しました
  （ライトの最小は情報の文字と背景の5.3:1、ダークの最小は情報の6.4:1）。
- 状態は色だけで示さず、必ず記号（✓ ✕ ! … – ● ◆ ■）と文字を併記します。
- 文字はOS標準のフォント（system-ui、ヒラギノ、Noto Sans JP、Yu Gothic UI等）を使い、
  フォントを同梱しません。本文16px、行の高さ1.7です。
- 余白は4・8・12・16・24・32pxの6段階、角の丸みは8pxです。
- 部品は、パネル、案内（正常・注意・失敗・情報）、状態の札、入力元の札、ボタン
  （主・通常・停止・録画・リンク）、詳細欄、映像の領域の7種類です。
- 無効なボタンは破線の枠と補足の文字の色にし、無効な理由を近くの文で示します。
- ダークモード（`prefers-color-scheme`）と動きを減らす設定（`prefers-reduced-motion`）に対応します。

## キーボード操作とアクセシビリティ

- タブはWAI-ARIAのタブの形式です。左右の矢印・Home・Endで移動し、選択中のタブだけが
  Tabキーの移動先になります。
- 先頭に「本文へ移動」のリンクを置きます。フォーカスは3pxの黄色の輪郭で表示します。
- 「視聴する」等でタブを移ったときは、移動先の見出しへフォーカスを移します。
  再生欄を閉じたときは、開いたボタンへフォーカスを戻します。
- 局のボタンは「局名、リモコン番号、物理チャンネル、入力元、受信中」を区切った読み上げ名を持ち、
  選択中を`aria-pressed`で示します。
- 状態の変化（スキャン開始・完了、選局、録画の開始・停止、通信断と復帰）は、
  一つの`aria-live`領域で読み上げます。毎秒変わる残り時間は読み上げ対象にしません。
- 入力欄・ラジオボタン・選択欄にはすべてラベルを付けます。操作の対象は高さ44px以上です。
- 画面幅が420px以下ではタブを詰め、700px以下では局の表をカードに、900px未満では視聴タブを
  一列にします。375px幅で横方向のスクロールが出ないことを確認しました。

## 実装の構成

| ファイル | 役割 |
|---|---|
| `src/sdr_dtv_poc/static/index.html` | 外部のCSS・JSだけを読み込むページの骨組み |
| `src/sdr_dtv_poc/static/style.css` | 色・文字・余白の規則と部品のスタイル |
| `src/sdr_dtv_poc/static/app.js` | 三つのタブの画面、状態の管理、ポーリング |
| `src/sdr_dtv_poc/static/api.js` | 画面とデータ供給の境界。現在は模擬データだけを返す |
| `src/sdr_dtv_poc/static/mock.js` | 表示確認用の模擬データと、状態が時間で進む模擬処理 |

- Vueは同梱済みのruntime-onlyのglobal build（3.5.22）です。テンプレートを使わず、
  `Vue.h()`の描画関数で画面を組み立てます。既存のCSPは変更していません。
  インラインのスクリプト・スタイル、`eval`、外部CDNを使いません。
- hls.js（1.6.13）は今回読み込みません。プレイヤーの処理は#29で`player.js`として追加する想定です。
- `api.js`の`SdrApi.create({mode: 'mock'})`だけが動きます。`mode`が`mock`以外なら例外にし、
  模擬処理の失敗時に実APIへ切り替える経路を持ちません。`mock.js`は`fetch`等の通信を使いません。
- ポーリングは一つのタイマーで行い、受信・スキャン・録画が動いている間は1秒、それ以外と
  通信断の間は5秒ごとです。応答は表示中のIDと照合し、別のIDの遅れた応答を捨てます。
  ページを離れるときにタイマーを止めます。
- 録画の残り時間は、サーバー（模擬処理）が返す値を表示するだけです。ブラウザーのタイマーで
  録画を止める処理はありません。5分の停止はバックエンドの単調時計で行う前提です。
- 模擬処理は、同じ`request_id`での再送に同じIDを返すこと、録画中の選局・スキャン・二重録画、
  残り時間が305秒未満の録画開始を409で拒否することを再現します。

### `api.js`の関数と、PR #31統合後のAPI

| 関数 | 接続先のAPI | 状況 |
|---|---|---|
| `bootstrap()` | `GET /api/bootstrap` | 実装済み。#29で`csrf_token`を保持し、変更操作に`X-CSRF-Token`を付ける |
| `status()` | なし | **仮**。動作中のID、復元の状態、空き容量をまとめて返すAPIを提案 |
| `diagnostics(inputKind)` | `GET /api/diagnostics?input_kind=` | 実装済み。応答の形をそのまま使う |
| `services()` | `GET /api/services` | 保存された局の一覧。初回のスキャン前は空配列 |
| `startScan(channels, request_id)` | `POST /api/scans` | 合成入力で実装済み。`input_kind`を明示し、最初は合成13・14chを使う |
| `getScan(id)`、`stopScan(id)` | `GET /api/scans/{id}`、`POST …/stop` | 実装済み。進捗・結果のフィールドは引継ぎの対応表に従う |
| `startSession(serviceRef, request_id)` | `POST /api/sessions` | 保存されたServiceの`id`を`service_key`で渡す。600秒とHLS有効化を明示する |
| `getSession(id)`、`stopSession(id)` | `GET /api/sessions/{id}`、`POST …/stop` | 実装済み。局の情報は`service`、HLSは`hls`に含まれる |
| `startRecording(sessionId, request_id)` | `POST /api/recordings` | 実装済み。`session_id`と`duration_seconds:300`を渡す |
| `getRecording(id)`、`stopRecording(id)`、`recordings()` | `GET /api/recordings/{id}`、`POST …/stop`、`GET /api/recordings` | 実装済み。partial・file_available・download_urlを照合する |
| 録画の再生・ダウンロード | `POST /api/recordings/{id}/playback`、同URLのGET、`GET …/download` | POSTで変換開始、GETは状態取得のみ。模擬画面は呼ばず、#29で接続する |

エラーは既存の`{"code": "...", "message": "..."}`を前提にし、`api.js`で

## 模擬画面が使う仮の応答（実APIではない）

以下は画面に必要な項目を示すための**仮の応答**です。サーバーの仕様として確定したものではありません。
画面作成時の応答を、模擬処理の読解用に残しています。以下の項目を現行`models.py`へ
追加する指示ではありません。接続時は上の対応表と#29への引継ぎに沿って画面の参照を変更します。

### 全体の状態（仮: `GET /api/status`）

再読込・別のタブで動作中の受信へ表示を結びつけ、開始できない理由を先に示すために使います。

```json
{"active_session_id": null, "active_scan_id": null, "active_recording_id": null,
 "restore": "verified", "storage": {"ok": true, "free_bytes": 51539607552},
 "server_time": "2026-10-04T03:00:00Z"}
```

### 局（`Service`への追加は仮）

```json
{"id": "live-15-4101", "name": "架空テレビA", "input_kind": "live",
 "physical_channel": 15, "service_id": 4101, "detection_stage": "ts_si",
 "remote_control_key": 3, "detected_at": "2026-10-03T01:00:00Z", "scan_id": "…"}
```

- `remote_control_key`、`detected_at`、`scan_id`は仮です。ONID・TSIDも保存キーに必要ですが、
  画面では使わないため仮の応答に含めていません。
- `detection_stage`の値は、既存の`synthetic_definition`に加えて`signal`・`tmcc`・`ts_si`を仮定しました。

### 受信セッション（`Session`への追加は仮）

```json
{"id": "…", "request_id": "…", "input_kind": "live", "source_id": "board",
 "state": "running", "stage": "transport", "duration_seconds": 600,
 "started_at": "…", "deadline_at": "…", "ended_at": null, "end_reason": null,
 "error_stage": null, "restore": "pending", "partial": false, "bytes_received": 12000000,
 "artifact_id": null,
 "service_ref": "live-15-4101", "service_name": "架空テレビA", "physical_channel": 15,
 "service_id": 4101, "remaining_seconds": 571,
 "health": {"signal": "ok", "ts": "ok", "cas": "ok", "hls": "ok"}}
```

- 模擬処理の選局には`service_ref`を使います。実APIでは確定済みの`service_key`へ対応させます。
- `remaining_seconds`はサーバーの時計で計算した残り秒数です。端末の時計のずれを避けるため、
  模擬画面では`deadline_at`との差を計算しません。実APIにこの項目はなく、#29では
  推定の残り時間表示と、サーバーが判定する録画開始の可否を区別します。
- `health`の各値は`waiting`・`ok`・`failed`・`blocked`・`not_required`を仮定しました。
  電波・TS・カード/CAS・変換の失敗を分けて表示するために必要です。
- HLSのURL（またはHLSのartifact ID）も#29で必要ですが、模擬では使わないため含めていません。

### スキャン（仮）

```json
{"id": "…", "request_id": "…", "state": "running", "channels": [13, 14, 15],
 "duration_seconds": 180, "started_at": "…", "deadline_at": "…", "ended_at": null,
 "end_reason": null, "restore": "pending", "done_channels": 2, "current_channel": 15,
 "found_services": 0,
 "results": [{"physical_channel": 13, "stage": "none", "services": []}],
 "saved": false}
```

`saved`は、このスキャンで保存した局一覧を置き換えたかどうかです。
模擬では「全範囲を調べ終えて1局以上見つかったときだけ置き換える」としました。

### 録画（仮）

```json
{"id": "…", "session_id": "…", "service_id": "live-15-4101", "service_name": "架空テレビA",
 "physical_channel": 15, "input_kind": "live", "state": "running",
 "started_at": "…", "ended_at": null, "duration_limit_seconds": 300,
 "elapsed_seconds": 42, "remaining_seconds": 258, "end_reason": null, "partial": false,
 "size_bytes": 84000000, "artifact_id": null,
 "playback_available": false, "download_available": false}
```

録画時の局名を`service_name`として保持し、後で局一覧が変わっても録画一覧の表示が変わらないようにします。
録画の`service_id`は局の`id`（文字列）で、放送のservice ID（数値）とは別です。#29で名前を整理してください。

### エラーコード

既存のコードは`restore_unverified`、`session_busy`、`storage_full`、`request_id_reused`、
`live_not_implemented`、`source_missing`、`source_not_registered`、`database_error`、
`session_history_limit`、`feature_not_implemented`、`*_not_found`、`invalid_request`をそのまま使います。
次のコードは仮です: `scan_active`、`recording_active`、`recording_time_insufficient`、
`session_not_running`、`service_not_found`、`scan_not_found`、`recording_not_found`。
`stop_timeout`は画面の内部だけで使うコードで、APIへの追加は求めません。

## PR #32時点の仕様と、当時#29へ残した接続作業

- 選局は`service_key`。スキャンで見つかった局は順次保存し、中止・失敗でも過去の一覧を消しません。
  模擬処理の`saved`判定を実APIの保存条件にしないでください。
- partialの録画はダウンロード・再生を拒否します。録画中に受信を先に停止すると
  `failed/partial/source_ended`です。模擬処理もPR #32のレビューでこの終了理由へ修正済みです。
- CAS・変換の故障は`hls.error_code/error_stage`、ブラウザーでの再生失敗はvideo/hls.jsの
  イベントで判断します。映像・音声を実際に再生できたかは#29で接続して確認します。
- 全体状態の`/api/status`は未実装です。一覧APIからの動作中IDの取得と、取得できない
  復元ゲート全体・残り入力時間の扱いは[#29への引継ぎ](issue-29-handoff.md)に従います。
- 受信は最大600秒ですが、合成入力は360秒でEOFになります。300秒録画には受信期限と
  入力残量の両方に305秒以上が必要です。画面だけで録画可能と決めず、APIの拒否理由を表示します。
- 録画一覧からの削除は初期範囲に含めません。容量不足の案内から勝手にファイルを削除しません。
