# USB切断後に視聴を再開する

WebUIの「受信機の復旧が必要です」が出た場合は、次の順に操作してください。

1. ボードに異常な発熱がないことを確認します。異常がある場合は復旧操作をせず、使用を止めます。
2. RFケーブルはそのままにして、ボードのSLAVE端子につながるUSBケーブルを一度抜き差しします。
   接続後、10秒ほど待ちます。
3. WebUIの「異常な発熱がないこととUSBの接続を確認しました」にチェックを入れ、
   **受信機を確認して復旧する**を押します。
4. 最大30秒で結果が出ます。成功すると警告と視聴・スキャンの制限が解除されます。
   **視聴タブで局を選んで**再開してください。受信・録画は自動再開しません。

## 「受信機に接続できません」が続く場合

USB接続が正しくても、Ubuntu側の一時的な通信設定が終了している場合があります。
Ubuntuのターミナルでこのリポジトリのフォルダーに移動し、設定済みの環境ファイルを
指定して次を実行します。

```sh
uv run --locked python scripts/live-start.py data/live.env
```

sudoの認証を求める案内が出た場合は、Ubuntu側で`sudo -v`を実行してから、同じコマンドを
もう一度実行してください。WebUIへパスワードを入力する必要はありません。
既存の設定と録画を使い、ホストの一時準備とWebUIの起動をまとめて行います。
環境ファイルの場所が異なる場合は、そのパスを指定します。Composeのプロジェクト名を
変更している場合は`--project NAME`を追加します（既定は`sdr-stage3-live`）。

[WebUI](http://localhost:18335/)を再読み込みして、手順3の復旧ボタンを押します。
ホスト準備は約57分で終了します。終了後は同じ起動コマンドで準備できます。
設定ファイルを変更した場合やホスト準備をやり直す場合は、視聴・録画を停止し、
同じコマンドに`--restart-host`を追加してください。前の準備の後始末を待ってから再開します。
ホスト準備中のUSB再接続では、一時的な通信設定を再設定します。復旧確認や受信自体を
勝手に開始することはありません。

## ほかのエラー

- 「別の処理が受信機を使用しています」: ほかの受信ツールを通常の停止操作で終了してから再試行します。
- 「受信機の設定を確認できません」: 受信前または中断時の設定と一致しないため、自動では書き換えません。
  ほかのツールや別の機器を使っていないか確認してください。
- 「復旧の確認記録を作成できません」: 受信前の設定など、復旧に必要なデータが不足しています。
  データフォルダーを削除せず、管理者による確認が必要です。
- 「受信機の復旧に失敗しました」: 接続が不安定な可能性があります。USB接続とホスト準備を確認してください。
  繰り返す場合は使用を止めて機器・ケーブルを確認します。

この操作は受信前のRX設定を復元し、別の接続で一致を読み戻してから制限を解除します。
ファームウェアの更新、工場出荷時へのリセット、送信機能の操作は行いません。
ソフトウェアの再起動だけでは、未確認の状態を消しません。実機では既に復元済みで
アプリ側の記録だけが未確認の場合も、保存された独立確認の結果を照合して復旧します。
失敗した受信や途中までの録画の記録は残します。
